# 🧪 Testing Tools Outside Adobe Animate

These Node.js scripts (independent of the JSFL toolchain) let you test
`modules/godotBuilder.jsfl` and `modules/inspector.jsfl` **without opening
Adobe Animate**, starting from a `debug_data.json` already extracted from a
real `.fla` (automatically generated by `main.jsfl` on every export, see
the main readme).

## Why

`_processElementNode` and the rest of the generation pipeline are dense,
stateful, and sensitive to numeric precision (geometry, gradient
matrices). A regression there is easy to introduce and hard to spot
without reopening Adobe Animate + Godot on every attempt. This safety net
was built after a real regression (v4.12, see the version history further
down in that readme) that would have been caught immediately with this
tool.

## Usage

### 1. Repair an old `debug_data.json` (if needed)

`debug_data.json` files generated **before** the `jsflStringify` fix (see
"Version History > main.jsfl" in the main readme) are not strictly valid
JSON (unescaped control characters inside pasted ActionScript code). A
**fresh** export doesn't need this step:

```
node tools/repair_debug_json.js path/to/debug_data.json
```

Writes `debug_data.repaired.json` next to the original.

### 2. Compare two versions of the pipeline

```
# 1. BEFORE modifying godotBuilder.jsfl/inspector.jsfl:
node tools/pipeline_snapshot.js debug_data.json /tmp/before

# 2. Make the change in modules/...

# 3. AFTER:
node tools/pipeline_snapshot.js debug_data.json /tmp/after

# 4. Compare:
diff -rq /tmp/before /tmp/after
```

Every difference must be **explainable** by the intended change. An
unexpected difference = a regression caught before even opening Godot.

### 3. Compare against a historical version (git)

```
git show <commit>:modules/godotBuilder.jsfl > /tmp/old_builder.jsfl
BUILDER_PATH=/tmp/old_builder.jsfl node tools/pipeline_snapshot.js debug_data.json /tmp/old_output
node tools/pipeline_snapshot.js debug_data.json /tmp/new_output
diff -rq /tmp/old_output /tmp/new_output
```

## Known limitations

- `nextId()` is made deterministic (a counter instead of `Math.random()`)
  to allow a byte-for-byte diff between two runs — without this, every
  resource ID would change on every run even with no code change at all.
- `FLfile.exists()` always returns `false`: no `project.godot` is
  simulated, so `RES_PREFIX` stays `res://` (instead of the
  `res://subfolder/` a real export into a project subfolder would
  compute). Only affects `ext_resource` paths, not node structure — no
  impact when comparing two versions of the code against each other.
- `FLfile.listFolder()` always returns `[]`: no external PNG texture is
  simulated. Shapes using `customTexPath` (imported bitmaps) are not
  exercised by this harness.
